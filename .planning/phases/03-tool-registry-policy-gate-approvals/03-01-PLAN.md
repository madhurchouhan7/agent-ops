Implement the allow-listed tool registry, code-level policy gate with risk tiers (T0-T3), and human-in-the-loop (HITL) approval lifecycle.

    Implement durable approval records, reviewer authorization, and rejection safety:
    1. In `src/agent_ops/storage/models.py`:
       - Add `ApprovalModel(Base)`: `id (str PK)`, `run_id (str FK runs.id)`, `tool_name (str)`, `arguments_json (JSON)`, `status (str: PENDING, APPROVED, REJECTED, EXPIRED)`, `policy_reason (str)`, `decision_actor (str | None)`, `decision_reason (str | None)`, `created_at (datetime)`, `decided_at (datetime | None)`.
    2. In `src/agent_ops/storage/approval_service.py`:
       - `ApprovalStatus(StrEnum)`: `PENDING`, `APPROVED`, `REJECTED`, `EXPIRED`.
       - `ApprovalService`:
         - Method `request_approval(session: Session, run: Run, tool_name: str, arguments: dict[str, Any], reason: str, runtime: WorkflowRuntime) -> ApprovalModel`:
           - Pauses run via `runtime.pause(run)`.
           - Creates and persists `ApprovalModel` in `PENDING` status.
           - Emits `approval.requested` event to `run_events`.
         - Method `submit_decision(session: Session, approval_id: str, actor: str, actor_roles: set[str], approved: bool, reason: str | None = None) -> ApprovalModel`:
           - Verifies server-side authorization: requires `"reviewer"` or `"admin"` in `actor_roles`. If not, raises `AgentOpsError("UNAUTHORIZED_REVIEWER", error_code="UNAUTHORIZED")`.
           - If approved: marks `status="APPROVED"`, emits `approval.approved` event.
           - If rejected: marks `status="REJECTED"`, emits `approval.rejected` event.
         - Method `can_execute_protected_action(session: Session, run_id: str, tool_name: str) -> bool`:
           - Returns `True` ONLY if an approval record exists with status `APPROVED`.
    3. In `tests/unit/test_approvals.py`:
       - Test creating an approval request automatically pauses the workflow run.
       - Test submitting decisions requires authorized roles; unauthorized callers are rejected.
       - Test that when an approval is REJECTED, `can_execute_protected_action` returns False and executing the tool is blocked.
       - Test that when an approval is APPROVED, the workflow resumes and executes the protected tool action.
       - Test that approval state survives database session restart.
  </action>
  <verify>uv run pytest tests/unit/test_approvals.py; uv run pytest --cov=agent_ops; uv run mypy</verify>
