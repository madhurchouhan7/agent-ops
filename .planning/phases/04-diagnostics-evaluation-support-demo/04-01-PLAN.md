  <action>
    Implement recursive credential scrubbing and failure capsule export:
    1. In `src/agent_ops/diagnostics/redactor.py`:
       - `RedactionEngine`:
         - Sensitive key blacklist: `api_key`, `secret`, `token`, `password`, `auth`, `authorization`, `cookie`, `access_token`, `private_key`.
         - Sensitive regex patterns: `(?i)bearer\s+[a-z0-9_\-\.]+`, `sk-[a-zA-Z0-9]{20,}`, `ghp_[a-zA-Z0-9]{36}`.
         - Recursive `redact(data: Any) -> Any`: traverses dicts, lists, sets, and strings, replacing secrets with `"[REDACTED]"`.
    2. In `src/agent_ops/diagnostics/capsule.py`:
       - `FailureCapsule(BaseModel)`: `capsule_version: str = "1.0"`, `run_id: str`, `workflow_id: str`, `workflow_version: str`, `error_code: str`, `error_message: str | None`, `created_at: datetime`, `failed_at: datetime`, `timeline: list[dict[str, Any]]`, `checkpoints: list[dict[str, Any]]`, `final_state: dict[str, Any]`, `redacted: bool = True`.
       - `CapsuleService`:
         - Method `export_capsule(session: Session, run_id: str) -> FailureCapsule`:
           - Verifies `run.status == "FAILED"` (raises `AgentOpsError("Run is not in FAILED status", error_code="INVALID_RUN_STATE")` otherwise).
           - Fetches run events and checkpoints.
           - Uses `RedactionEngine.redact` to scrub timeline events, checkpoints, and final state.
           - Returns `FailureCapsule`.
    3. In `tests/unit/test_redaction_capsules.py`:
       - Test that nested secrets in dicts, lists, and strings are replaced with `[REDACTED]`.
       - Test that exporting a capsule on a failed run produces a valid, redacted JSON-serializable capsule.
       - Test that attempting to export a capsule for an in-flight or succeeded run fails closed with `INVALID_RUN_STATE`.
  </action>
  <verify>uv run pytest tests/unit/test_redaction_capsules.py; uv run mypy</verify>
  <done>
    RedactionEngine scrubs all sensitive keys and token formats, CapsuleService exports redacted failure capsules for failed runs, and unit tests pass.
  </done>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client -> Control API | HTTP requests must be authenticated, authorized, and validated with strict schemas |
| API -> Failure Capsule Export | Internal state/events exported to external users; all credentials must be scrubbed |
| Replay Engine -> Host/Network | Replay must never make network requests or trigger side effects |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Information Disclosure | CapsuleService / RedactionEngine | high | mitigate | Recursive redaction replaces passwords, API keys, and authorization headers with `[REDACTED]`. |
| T-04-02 | Elevation of Privilege | ApprovalDecision Endpoint | high | mitigate | Server-side role verification requires `reviewer` or `admin` role from request headers/context. |
| T-04-03 | Denial of Service | API Run Creation | medium | mitigate | Idempotency keys prevent duplicate runs and step budgets prevent runaway loop execution. |
| T-04-04 | Tampering | MockReplayRunner | high | mitigate | Replay executes purely from recorded history without network sockets or unmocked external side effects. |
</threat_model>
